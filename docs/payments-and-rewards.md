# Оплата задач и программа «Огоньки»

## Текущее состояние

- Заказчик и исполнитель договариваются напрямую. Приложение не принимает деньги и не перечисляет выплаты.
- Для новых объявлений сохраняется планируемая комиссия площадки: 5% за обычную задачу и 7% за срочную. Это информационное значение, списаний нет. Старые объявления сохраняют прежнее значение до редактирования.
- После подтверждения выполнения заказчиком исполнитель получает один огонёк за календарный день по времени Красноярска. Повторное подтверждение и несколько задач за день не дают дополнительные огоньки.
- На 5-й день подряд записывается заявка на награду 150 ₽, на 10-й — отдельная заявка на 300 ₽. Статус `pending_review` означает, что деньги не выплачены. Ни API, ни интерфейс не имеют команды самостоятельного перевода награды.
- Подтверждение заказчика пока не доказывает реальное выполнение или оплату. Перед начислением денег нужно сверять оплаченные сделки, личности участников и признаки накрутки.

## Рекомендуемый способ оплаты

**ЮKassa «Безопасная сделка»** подходит для площадки, где физлица оказывают друг другу услуги. Платформа создаёт сделку, заказчик оплачивает её через платёжную форму ЮKassa, после подтверждения результата исполнитель получает выплату на карту через сервис, а площадка — своё вознаграждение. Данные карты следует собирать только виджетом провайдера, не в нашей базе и не в собственном поле формы. Рекомендуемый момент вознаграждения площадки — закрытие сделки: так возвраты проще согласовать.

До запуска требуются оформленная деятельность и договор с ЮKassa, тестовый и боевой `shopId` и секретный ключ, согласование тарифов и правил возврата, юридические документы для пользователей и проверка расчётов с исполнителями. ЮKassa взимает свою комиссию; 5/7% — комиссия площадки, её нельзя считать чистой прибылью. Награды 150/300 ₽, эквайринг, возвраты и налоги должны быть включены в финансовую модель.

## Порядок внедрения после получения доступа

1. Создать таблицу `deals` с `task_id`, `application_id`, суммой в копейках, ставкой и суммой комиссии, ID сделки/платежа/выплаты ЮKassa, состояниями и временными метками. Для каждого перехода хранить событие в отдельном журнале с уникальным ID провайдера.
2. После выбора исполнителя создавать сделку с уникальным ключом идемпотентности. Сервер берёт сумму и срочность из базы; браузер не передаёт итоговую сумму или ставку как источник истины.
3. Отправлять заказчика в платёжную форму провайдера. Статус оплаты менять только после проверки ответа API ЮKassa или уведомления с дополнительной сверкой по API; возврат пользователя на сайт не означает успешный платёж.
4. После подтверждения выполнения выполнять выплату по токену карты провайдера. Не хранить номер карты, CVC и полные реквизиты. Выплату и получение комиссии подтверждать отдельными событиями провайдера.
5. Огонёк для денежной награды считать подтверждённым только по завершённой оплаченной сделке без возврата. Заявки на награды проверять на связанные аккаунты, повторяемые пары заказчик/исполнитель и подозрительные цены. Проводить награды отдельным платёжным потоком после проверки, с повторяемой сверкой реестров.
6. Обработать ошибки, отмену, частичный/полный возврат, недоступность провайдера, повторные уведомления и расхождение данных. Добавить операторский журнал и ежедневную сверку реестров.

Источники: [основы Безопасной сделки](https://yookassa.ru/developers/solutions-for-platforms/safe-deal/basics), [сценарий доски объявлений](https://yookassa.ru/developers/solutions-for-platforms/safe-deal/quick-start/advertisement), [выплаты](https://yookassa.ru/developers/solutions-for-platforms/safe-deal/integration/payouts), [реестры](https://yookassa.ru/developers/solutions-for-platforms/safe-deal/reports).

## Вход по почте

API входа по шестизначному коду и привязки почты подготовлен. Отправка включается только при наличии `RESEND_API_KEY`, `RESEND_FROM` (адрес на подтверждённом домене) и `EMAIL_OTP_SECRET` (случайный секрет для HMAC кодов). Эти значения должны храниться в секретах окружения, не в репозитории. Код действует 10 минут, ограничены запросы и число проверок. Пока конфигурации нет, интерфейс входа по почте скрыт. Бесплатный тариф Resend на дату проверки: 3 000 писем в месяц, не более 100 в день; необходим подтверждённый домен. Источники: [тарифы](https://resend.com/pricing), [подтверждение домена](https://resend.com/blog/new-domain-verification-experience).
