# Рядом

[Открыть рабочий сайт](https://ryadom.ivanfomin2003.chatgpt.site/)

Поручения и подработка в Красноярске. Веб-приложение на React / Vinext, Cloudflare Workers, D1 и R2.

## Что работает

- Регистрация по имени, логину и паролю, серверные сессии.
- Публикация объявлений, категории, бюджет, срочность и районы.
- До пяти фотографий в объявлении; загрузка JPEG, PNG и WebP до 3 МБ на файл, хранение в R2.
- Форматы «На месте» и «Удалённо». Удалённым задачам не нужны адрес и район; в блоке карты они показаны отдельным списком без фиктивной точки дома.
- Подсказки адресов Красноярска при вводе, выбор клавиатурой и автоматическая подстановка района, если он есть в данных. Район можно исправить вручную. Photon используется для подсказок с задержкой, отменой старых запросов, лимитами и кешем; Nominatim — только для явной проверки полного адреса.
- Поиск, избранное и встроенная карта Яндекса с собственным управлением масштабом и жестами. Выбор объявления под картой приближает его адрес; кнопка «Открыть» показывает подробности. Геокодирование адресов использует OpenStreetMap/Nominatim.
- Отклики, выбор исполнителя и подтверждение завершения заказчиком.
- Собственные и публичные профили, фото и описание.
- Оценки и отзывы только от участников завершённых задач.
- Уведомления внутри сайта и в собственном профиле об откликах, выборе исполнителя и завершении.
- Личные чаты по каждому отклику, включая ранее созданные: текст, фотографии, непрочитанные сообщения и загрузка истории. Доступ к переписке и её фото проверяется на сервере для заказчика и автора отклика. Черновые фотографии не публичны.

## Проверка с другом

1. Оба откройте **рабочий сайт по ссылке выше**, каждый со своего устройства, и зарегистрируйте отдельный аккаунт.
2. Первый пользователь публикует задачу, второй откликается.
3. Первый получает уведомление и выбирает исполнителя из откликов.
4. Второй получает уведомление о выборе. Откройте «Написать в чат» у отклика или значок сообщений в шапке. Отправьте сообщение и фото с обоих устройств.
5. После фактического выполнения заказчик подтверждает завершение, участники оставляют отзывы.

Уведомления проверяются каждые 10 секунд, пока вкладка активна, и при возвращении на сайт. Это не push-уведомления, не SMS и не письма.
Открытый чат обновляется каждые 3 секунды; список переписок — каждые 10 секунд. Отправки имеют ключ повторного запроса, чтобы сетевой повтор не создавал дубликат. В чатах не следует передавать платёжные реквизиты или документы.

## Важные ограничения

Это версия для совместного тестирования, а не полностью готовый коммерческий маркетплейс. Платежи и фактическое удержание комиссий, верификация возраста, модерация, споры и восстановление пароля ещё не подключены. Срочность сейчас влияет на выдачу; показанная комиссия является расчётной и не списывается. Рейтинг не подтверждает личность пользователя.

Платёжная интеграция не реализована и не имитируется. Для реальных резервирований и выплат требуется согласованное с провайдером подключение площадки, договор и серверные секреты. Простая форма перевода владельцу сервиса не заменяет безопасную сделку. После подключения необходимы подтверждение статуса оплаты сервером провайдера, идемпотентность, обработка уведомлений, возвратов и выплат, запрет начала оплачиваемой работы до подтверждённого резерва и испытания в тестовой среде. Документация: https://yookassa.ru/developers/solutions-for-platforms/safe-deal/basics

Публичный сервер Photon предназначен для умеренной нагрузки и не предоставляет SLA. Для роста аудитории нужен выделенный/договорной геокодер. Покрытие домов и районов зависит от OpenStreetMap; ручная проверка остаётся доступна. Есть ограничения размера и частоты загрузок, но автоматическая модерация фото, антивирус и очистка неиспользованных загрузок пока отсутствуют.

GitHub хранит исходники. GitHub Pages не исполняет серверную часть этого приложения. Общая база данных и фотографии размещены на рабочем хостинге, отдельно от репозитория. Локальная версия использует отдельную базу — данные localhost не переносятся на публичный сайт автоматически.

## Локальная разработка

Требуется Node.js >= 22.13.

```sh
npm ci
npm run build
npm start -- --port 4173
```

Перед первым запуском примените миграции `drizzle/*.sql` к **локальной** D1 последовательно. Не запускайте уже применённую миграцию повторно:

```sh
node --import ./scripts/sites-env.mjs node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_right_meggan.sql
```

Повторите команду для остальных миграций по порядку. Локальные данные хранятся в игнорируемой Git папке `.wrangler/state`.

Проверки: `npm run lint`, `npx tsc --noEmit`, `npm run build`.

## Публикация

Рабочая публикация использует Workers + D1 (`DB`) + R2 (`BUCKET`). Миграции версии применяются перед публикацией. Пароли хешируются, сессии отзываются при выходе. Секреты, токены, пользовательская база и загруженные фото не должны попадать в Git.
